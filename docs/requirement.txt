# 🗄️ DATABASE DESIGN (VERY IMPORTANT)

## 1️⃣ Roads Table

```sql
CREATE TABLE roads (
  id INTEGER PRIMARY KEY,
  from_node TEXT,
  to_node TEXT,
  distance REAL
);
```

---

## 2️⃣ Road Metrics Table

```sql
CREATE TABLE road_metrics (
  road_id INTEGER,
  surface_condition INTEGER,
  traffic_density INTEGER,
  safety_score INTEGER,
  weather_impact INTEGER,
  obstacle_count INTEGER,
  last_updated DATETIME
);
```

---

## 3️⃣ Complaints Table

```sql
CREATE TABLE complaints (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  road_id INTEGER,
  complaint_type TEXT,
  description TEXT,
  reported_by TEXT,
  timestamp DATETIME,
  status TEXT
);
```

Examples:

* pothole
* under construction
* muddy
* flooded
* accident

---

## 4️⃣ Reviews Table

```sql
CREATE TABLE reviews (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  road_id INTEGER,
  rating INTEGER,
  comment TEXT,
  user_name TEXT,
  timestamp DATETIME
);
```

# 📊 METRICS HANDLING (CORE LOGIC)

### Each road’s **final weight**:

```
weight =
  distance
+ obstacle_count * 2
+ (5 - surface_condition) * 2
+ traffic_density * 1.5
+ (5 - safety_score) * 1
+ weather_impact * 1
```

✔ Clear
✔ Logical
✔ Matches your abstract

# 🔁 DATA FLOW (USER → SYSTEM → USERS)

### Complaint Flow

1. User selects a road on map
2. Submits complaint (pothole, construction, etc.)
3. Backend stores it in DB
4. Road metrics auto-update
5. Other users immediately see:

   * Alerts
   * Changed route weight
   * Updated optimal path

---

### Review Flow

1. User rates road (1–5)
2. Review stored
3. Average safety / surface score recalculated
4. Influences future routes

---

# 🧠 DIJKSTRA PROCESS (BACKEND)

1. Fetch roads from DB
2. Fetch latest road metrics
3. Build weighted graph
4. Run **Enhanced Dijkstra**
5. Return:

   * Optimal path
   * Distance
   * Risk level
   * Warnings (obstacles, complaints)
